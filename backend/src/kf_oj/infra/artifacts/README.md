# 不可变工件

存储根配置于 `KF_OJ_ARTIFACT_ROOT`，由服务账号持有，目录 0700、文件 0600。
单件至多 64 MiB；默认总字节 512 MiB / 文件 4096，可在有界配置中调整。
发布采用摘要名称、临时文件、文件/目录 fsync 和跨进程锁；已有工件必须通过长度/摘要核验，
拒绝静默覆盖/修复，普通读取不跟随链接。锁等待最多五秒。临时文件也计入容量。

适配器执行已经授权的操作，不自行识别用户、租约或题库。公开样例由 problems 的公开 DTO
提供；个人源码由 submissions 的已验证主体与归属端口读取；隐藏数据只经有效当前租约取得。
没有匿名工件下载或由文件路径选择的读取接口。

发布事务先取得 digest 锁，再持久化字节与元数据，业务引用最后提交；事务回滚最多留下
无元数据的耐久孤立文件，不留下数据库引用指向未发布字节。回收使用同一 digest 锁，
业务引用的数据库生成 ready 状态及复合外键阻止被引用元数据转为 deleting。

`uv run --locked kf-artifacts --limit 100 [--after <digest>]` 执行有限回收批次：恢复 deleting、
标记超过一天的未引用元数据、删除耐久字节/元数据及超过一天的无元数据文件/临时文件。
每次扫描至多 100 行；显示游标，后续调用接续，避免固定前页上的保留工件阻塞扫描。
引用工件不能被回收。文件删除后事务失败仍保持 deleting，下一批可恢复；新引用无法加入。
需要已迁移数据库和有限平台权限；回收不遍历业务域 ORM，也不删除不可变题目版本。
